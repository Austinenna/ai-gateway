# WorkBuddy 按一次提问归组

首版只使用 WorkBuddy 兼容的显式请求头；一个任务表示一次用户提问涉及的网关 LLM 调用，包含共享根 ID 的子代理调用。同一个会话中的下一次提问另起一组。没有可靠标识的请求独立展示，不按时间间隔猜测，不回填旧记录。

## 页面使用

进入「请求记录」，顶部可切换「按任务 / 逐次调用」。发现带有效标识的 WorkBuddy 调用后，默认展示任务视图；只有旧记录时保留原逐次视图，也可手动切到任务视图查看独立条目。

任务列表直接显示提问摘录、分组来源、调用次数、输入／输出 Token、状态和失败次数。可按项目、关键词、已分组或需关注筛选；任务详情提供「对话概览 / 调用过程 / 分组信息」。调用过程可分页展开，主代理和子代理分开标注，点击单次调用复用消息、响应详情、原始数据复制和性能页。

## 请求正文的格式化阅读

USER 是接口中的消息角色，内容可能同时包含用户提问和客户端附加的环境、身份文件、项目上下文。WorkBuddy 常用 XML 风格标签包裹这些文本，内部又含 Markdown 和 YAML 文件头，它不是单一格式的文档。

消息区及任务提问概览可切换「格式化 / 原文」。USER 与 SYSTEM 使用同一套普通 Markdown 排版，只处理标题／列表／引用／代码等语法。原有 XML 风格标签、属性、字段名和文本顺序保留；不另外命名区块、不翻译字段、不按标签生成卡片或折叠，也不把 YAML 文件头改写成代码块。长消息沿用整体预览与展开全文。

排版组件为按需加载的 [react-markdown](https://github.com/remarkjs/react-markdown)，输入直接使用记录原文，不启用原始 HTML 执行；图片和不能安全跳转的链接保留其原始 Markdown 写法。原文模式保留精确字符串；完整请求 JSON 仍在「原始数据」页签，可按原有方式复制。显示组件不修改转发或存储正文。新增 Chat／Messages 模拟上游测试核对客户端传入、上游收到与记录保存的消息内容完全一致。

## 标识与保存

项目认证成功后才采集以下白名单字段，不保存整套请求头、Cookie 或 Authorization；这些字段不参与认证、路由，也不会随请求转发给厂商。

| 请求头 | 用途 |
| --- | --- |
| `X-Root-Request-ID` | 一次提问的根 ID，优先用于合并主代理与子代理 |
| `X-Conversation-Request-ID` | 轮次 ID；仅主代理没有根 ID、没有父会话时作为回退 |
| `X-Conversation-ID` | 当前代理的会话 ID，不单独作为任务 ID |
| `X-Parent-Conversation-ID` | 父会话关联信息 |
| `X-Agent-Type` | main / subagent / team |
| `X-Conversation-Message-ID` | 客户端单次调用 ID，仅供排查 |

任务 ID 为认证项目 ID、适配器名、根 ID 的 SHA-256，避免不同项目碰巧传同一个根 ID 时混组。字段只接受 1–256 个 ASCII 字母、数字、点、下划线、冒号、短横线；缺少必要字段、重复头、非法字段或子代理仅有自己轮次 ID 时保留独立调用。客户端标识是客户端提供的声明，并不证明客户端产品身份；兼容相同头的 CodeBuddy 也可能进入此适配器。

调用摘要新增 `task_id`、`grouping`、`question_excerpt`、`reply_kind`，兼容已有 JSON。提问摘录最多 1024 字符，从已经脱敏的输入中找最后一个包含文本的 user 消息，忽略仅有工具结果的消息；系统插入的 user 文本仍可能成为摘录，不能保证还原用户原始输入。正文仍使用原有记录，不重复存储完整对话。

现有两张记录表增加 JSON 表达式索引，无破坏性迁移。监控摘要优先于正文日志，正文日志丢失时仍计入已保存的调用；无法恢复从未经过网关、未提供标识或两类日志均未保存的调用。

## 管理接口

- `GET /api/admin/request-tasks`：最近 200 次已保存调用及当前活跃调用涉及的任务；每个返回任务的统计包含该组的全部已保存调用，不受 200 条窗口限制。历史无标识记录作为独立条目。
- `GET /api/admin/request-tasks/{id}?offset=0`：完整任务统计、按开始时间排列的调用摘要，每页 100 条，含 `total` / `has_more`；同毫秒以记录 ID 稳定排序。
- 原 `GET /api/admin/requests/{id}`：按需读取某次调用的输入、响应、性能和原始数据。

所有接口沿用管理会话认证。列表统计覆盖整个任务，筛选只决定展示哪些任务，不改变一个任务的统计范围。

## 状态与统计口径

- **调用中**：组内存在正在进行的 HTTP 调用。
- **已回复**：最新主代理调用成功，记录含正文、正常结束原因，且没有工具调用。并不等于客户端任务已结束。
- **等待后续**：没有正在传输的调用，但最新主代理只调用了工具、只有思考、未正常结束、正文被截断，或尚未捕获主代理。
- **调用异常**：最新主代理调用失败；后续成功主代理回复可恢复为已回复，但失败次数始终保留。

输入／输出 Token 分别累加已知数值，展示各自已知样本数，未知用量不当作 0。重试也按实际 LLM 调用累计；不凭失败后成功就断言重试关系。耗时为首个已记录调用开始至最后调用结束的时间跨度，包含间隙和并行，不是各次耗时相加。这里只描述网关观察范围，不推断未记录的前后步骤。

## 验证边界

本地 WorkBuddy 5.5.6 的代码中存在并构造这些请求头，自定义模型请求也走该路径。上线验证使用临时数据库、模拟上游和模拟 WorkBuddy 请求；实际安装版本、客户端配置或中间代理可能移除请求头，仍需用户下一次真实提问确认首组记录。不自动发起付费厂商调用。
