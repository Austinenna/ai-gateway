# 第一版 Demo：运行与使用

## 已实现的流程

这是可以在本机运行的 Go＋React／TypeScript＋Vite＋SQLite 应用。前端构建后嵌入 Go 可执行文件，运行时不需要 Node 服务。

1. 首次打开设置管理密码。当前本机启用自动解锁：已有密钥库仅首次切换需要原密码，之后每次启动即可调用；管理页可留空登录。
2. 在“厂商连接”选择智谱、MiniMax、DeepSeek、阿里百炼或自定义连接，启用所需的 Chat Completions／Anthropic Messages／百炼 ASR 协议并填写各自的基础端点；同一连接的协议共用厂商 Token。可以编辑、停用或重新验证密码查看 Token。
3. 在“模型配置”设置显示名称、调用别名、厂商模型 ID、关联连接、启用的协议和默认参数。
4. 在“项目权限”创建项目，勾选可调用模型，取得单独的项目凭证。在项目列表的“接入信息”中复制网关端点、完整 Token 或整份接入配置。
5. 程序用网关端点、项目凭证和模型别名调用。可以在页面的“试调用”里直接验证。
6. 在“请求记录”查看消息、响应详情、原始数据和性能与用量，也可按项目、状态和关键词筛选。“响应详情”整理上游实际返回的思考文本、回答正文、工具名称与参数、结束原因；流式片段会合并，多个工具调用分别展示，可独立折叠。没有回答正文不代表没有返回，消息页会提示已返回的思考／工具调用。工具执行结果由客户端带入后续请求，可在那条请求的 TOOL 消息中查看。点击 SYSTEM、USER、ASSISTANT 等角色标题可独立展开／收起消息，支持 Enter／空格操作；切换请求时恢复默认展开。

百炼 ASR 的配置、原生 JSON 请求示例与限制见 [百炼 ASR 接入](asr.md)。模型测试／项目试调用可选择音频和热词，请求记录展示转写内容、时间戳及音频秒数。音频正文只用于转发，不保存到记录；本轮未替用户修改 Dustoff 或迁移其 Key。

也可以在空白概览中点击“载入本地演示”：会创建模拟连接、模型和项目，并打开试调用。模拟模型直接在本机返回固定说明文字，不访问厂商、不消耗额度。它用于验证流程，不提供真实推理。

桌面管理页采用固定窗口布局：左侧菜单保持在窗口内，提供「概览、任务记录、请求记录、厂商连接、模型配置、项目权限」六个入口。「任务记录」按任务汇总调用，「请求记录」逐次展示请求，详情与统计边界见 [WorkBuddy 任务分组](workbuddy-tasks.md)。各页面统一使用紧凑页头，标题在左、常用操作在右，滚动时仍可直接使用；网关地址与运行状态位于侧栏底部。总览保留时间范围与筛选工具，配置说明放在对应表单中。

任务记录与请求记录页的列表和详情占满剩余高度、各自滚动，搜索和筛选保持可见；右侧页签吸顶，切换记录或页签后从顶部开始阅读，左侧列表位置保留。长消息通过预览与全文展开查看，没有消息内部的纵向滚动。展开试调用时恢复普通工作区布局，关闭后回到分栏。

其他页面由工作区独立滚动，切换页面时回到顶部，支持键盘翻页；矮窗口的侧栏可以滚动以露出底部操作。手机宽度下请求列表和详情上下排列，使用整页滚动，登录页也不受桌面滚动限制。

## 获取厂商模型列表

在新增／编辑模型窗口选择“所属连接”，点击厂商模型 ID 下方的 **获取模型列表**。双协议连接可以选择“获取协议”，只请求该协议端点的 `/models`；服务器使用已保存的厂商 Key，浏览器不会取得 Key。打开窗口、切换连接或修改表单不会自动访问厂商。

列表支持按 ID／显示名称搜索，默认显示前 10 个，也可选择 20／50／全部。有效时间按从新到旧排列；缺少有效时间的模型放在后面，按 ID 排列并标注“时间未知”；全部缺少时间时提示无法判断新旧，不从名称推测版本时间。显示的是厂商报告的创建／发布时间，不承诺是模型正式发布日期。筛选在获取的完整结果中进行，再限制显示数量。

点击候选项会同步填入厂商模型 ID、显示名称和调用别名：显示名称使用厂商名称，别名使用模型 ID；再次选择会重新填入这三项，填入后均可手动修改。启用协议保持不变。列表可能是平台目录而非当前套餐可用范围，可在保存后使用模型测试确认。接口不支持、凭据权限不足、返回格式不兼容或获取失败时显示原因，始终保留手动输入；不会转而请求其他域名或自动发起推理。

Messages 列表分页会合并、去重后再排序，最多获取 5 页／5000 条，每页最多 4 MB，总超时 15 秒。达到限制、游标重复或出现无法识别的分页时显示“仅获取了部分结果”，不声称已覆盖全部最新模型。选择“全部”表示全部已获取结果。关闭窗口、切换连接或获取协议会取消原请求并清除旧列表。

MiniMax 的两种列表格式已按[官方 Chat 列表](https://platform.minimax.cn/docs/api-reference/models/openai/list-models)和[官方 Messages 列表](https://platform.minimax.cn/docs/api-reference/models/anthropic/list-models)适配；自定义服务及智谱也可尝试同协议端点的 `/models`，是否可用以该端点实际响应为准，兼容推理协议不代表支持列表接口。自动化验证使用模拟上游，没有调用真实厂商。

## 试调用的项目凭证

试调用填写网关生成的完整 `gw_` 开头项目凭证。管理密码用于解锁，厂商 Token 填在“厂商连接”，项目列表显示的短前缀也不能用来调用。页面会检查凭证格式并去掉粘贴时首尾的空白；合法格式仍须通过后端鉴权和模型授权。

载入本地演示时，生成的项目凭证会自动填入。前端只在当前页面内存中暂存生成或填入的凭证；刷新、退出管理或检测到管理会话失效时清除，不写入 localStorage、sessionStorage 或其他浏览器持久存储。

点击“选择项目并填入”时，已加密保管的项目 Token 可通过管理接口取回并填入，刷新或重新登录管理页后仍可使用，不会更换凭证。项目停用时先调整权限。后端拒绝失效凭证后，会丢弃对应的页面暂存并提供重新取回入口。

## 复制项目接入信息

打开 **项目权限 → 对应项目行 → 接入信息**：

- **复制端点**：复制客户端所需的 Base URL，不读取项目 Token。Chat Completions 使用含 `/v1` 的地址；Anthropic SDK 使用根地址，由 SDK 添加 `/v1/messages`。
- **复制 Token**：只在点击时取回并复制完整项目 Token。平时仅显示前缀与遮罩；复制失败时可主动显示内容后手动复制。
- **复制完整接入配置**：复制包含 `BASE_URL`、`API_KEY`、`MODEL` 的三行配置。模型下拉只显示该项目已授权、与所选协议对应的模型别名。
- **重置项目 Token**：先展示旧 Token 失效提示，明确确认后才生成新 Token。取消或打开窗口不会重置。

新建、载入演示和重置得到的项目 Token 均加密保存在服务器，后续刷新、服务重启并登录管理页后仍能复制。复制原 Token 不改变权限或正在使用的配置。已停用项目仍可复制，但无法调用。

项目页按“项目／凭证、授权模型、状态、操作”展示整行列表。接入信息为主要操作，编辑权限、试调用和删除保持对齐；窄窗口按行分组，手机宽度下操作固定为两列。已用独立演示数据检查 2048、1440、1280、1024、390 像素宽度，以及长名称、多个模型、无授权、停用、深色模式和 200% 文字放大，未出现横向溢出或按钮重叠。

旧版数据库只保存项目凭证摘要，升级不能恢复原文。旧项目显示 **保存已有 Token**：粘贴自己已保存的完整 Token，经后端核对确实属于当前项目且仍有效后加密保管，原凭证保持有效。已经遗失时才需要明确重置。升级不会自动更换任何旧项目 Token。

管理接口 `POST /api/admin/projects/{id}/credential` 按需返回完整项目 Token；`POST /api/admin/projects/{id}/credential/save` 接受 `{token}` 保存已有有效值。两者均要求同源管理员会话、管理请求标记和已解锁的密钥库；普通项目 Token 无权访问。管理列表只返回 `has_saved_token` 和短前缀；凭证响应设置 `Cache-Control: no-store`，不写入请求记录。

## 删除配置

厂商连接、模型配置、项目权限的列表和编辑窗口均提供“删除”。确认窗口显示对象名称与具体影响，点击“确认删除”才执行；也可取消后改为停用。

| 删除对象 | 处理方式 |
| --- | --- |
| 厂商连接 | 删除窗口直接列出所有关联模型，包括已停用模型，以及每个模型的授权项目。可以在列表中逐个删除模型，也可点击“删除厂商及 N 个模型”一次删除连接、全部关联模型和对应授权；不会撤销厂商平台上的 Key。 |
| 模型 | 删除模型及各项目对它的授权，保留项目和连接。以后用同一别名新建模型，需要重新授权。 |
| 项目 | 删除项目、授权关系及加密保存的项目 Token，原项目凭证失效；保留模型和连接，并清理当前页面中对应的凭证暂存。 |

历史请求记录保留名称、别名和输入输出快照，不随配置删除；请求列表仍可筛选最近记录中的已删除项目和模型。删除只影响后续请求，不保证中断已开始的调用。

删除接口仅供已登录管理员使用，逐次校验来源及管理标记。级联删除通过 `DELETE /api/admin/connections/{id}?cascade=true` 提交窗口中展示的 `model_ids`，服务端在同一事务里核对完整列表、移除授权、删除模型与连接；任何一步失败全部回滚。关联模型发生变化时返回 409，点击窗口里的“刷新列表”核对后再操作。未明确选择级联的旧接口仍阻止删除有引用的连接。删除不存在对象返回 404。旧编辑窗口保存已删除对象会失败，不会重新创建该对象。

模型列表统一使用“编辑、测试、删除”文字操作，调整列宽、行距和状态展示；窄窗口自动切换为分行布局。厂商删除窗口中的关联列表独立滚动，底部保留总影响说明与级联删除按钮。已按 1440、1024、390 像素宽度检查截图、长名称、滚动和按钮可达性，并检查深色模式与 200% 文字放大。

## 本地临时空白解锁

当前 `scripts/start.sh` 添加了 `--local-no-password`。首次创建密钥库仍设置管理密码；旧密钥库第一次切换时，在登录页输入一次原管理密码，系统解密原主密钥并保存本地免密解锁材料。此后服务启动时自动解锁，无需打开页面或登录即可接收已授权项目的模型调用。自动解锁不会创建管理员会话；管理页面仍需点击“进入管理页面”，密码可留空。“退出管理”只撤销当前会话，其他会话和模型调用继续运行。厂商 Token 的查看窗口也可以空白点击“解锁查看”。

原管理密码包裹、厂商 Token、项目 Token 和授权均保留，不重置已有凭证。空白登录依然建立同源管理员会话；未登录的管理请求、跨站请求和缺少管理标记的请求仍会被拒绝。非空但错误的密码仍会失败。

这是本机临时模式：免密解锁材料使用空密码派生的密钥包裹，管理访问不再依赖密码保密，数据目录及备份应受本机权限保护。只有回环监听和回环管理地址能启用。直接运行二进制默认关闭此模式，未来 Linux 部署不默认免密。

恢复原密码登录：停止当前进程后运行 `bash scripts/start.sh --local-no-password=false`。启动时会移除活动数据库里的临时解锁材料，原管理密码仍然有效；历史备份中的材料不会随之删除。恢复后再次启用，需要重新输入一次原密码。

已有本地解锁材料损坏时，启动会明确报错，不静默启动一个无法调用的服务；可关闭免密模式后使用原密码恢复。旧库尚未完成切换时，无法从空白密码恢复已经加密的主密钥；页面会提示输入原密码，不会通过清空数据库或更换密钥绕过。

## 本机启动

在项目目录运行：

```bash
bash scripts/start.sh
```

打开 [本地管理页面](http://127.0.0.1:8317/)。首次设置至少 12 个字符的密码。Demo 不提供密码找回，请自行保存。

当前 Mac 的 Go 工具链位于项目 `.tools/go`，版本为 1.27.1，从 Go 官方下载并核对 SHA-256；没有修改系统 Go 或全局 PATH。源码依赖 Go 1.26 或更新版本。前端构建使用 Node 22.12+ 或兼容的新版本。本次使用 Node 24。

修改源码后重新构建并重启：

```bash
bash scripts/build.sh
bash scripts/start.sh
```

启动脚本默认数据目录为项目 `.data/`；二进制直接启动时默认使用操作系统的用户配置目录。数据路径与监听地址可指定：

```bash
./bin/gateway --data-dir /path/to/gateway-data --addr 127.0.0.1:8317
```

一个端口只运行一个实例。停止时在启动终端按 Ctrl+C；服务关闭前等待请求结束／取消并排空记录队列。不要用强制结束进程代替正常停止。

## 真实模型配置

一条连接可以配置所需协议的基础端点。每个端点包含版本路径；网关根据客户端请求路径确定协议，再选择该协议的端点并添加末尾调用路径：

| 厂商／协议 | 基础端点示例 | 网关添加 |
| --- | --- | --- |
| 智谱 Chat Completions | `https://open.bigmodel.cn/api/paas/v4` | `/chat/completions` |
| 智谱 Anthropic Messages | `https://open.bigmodel.cn/api/anthropic/v1` | `/messages` |
| MiniMax Chat Completions（中国站） | `https://api.minimax.cn/v1` | `/chat/completions` |
| MiniMax Messages（中国站） | `https://api.minimax.cn/anthropic/v1` | `/messages` |
| MiniMax 国际站 | 使用账号对应的 `api.minimax.io` 端点 | 同协议路径 |
| DeepSeek Chat Completions | `https://api.deepseek.com` | `/chat/completions` |
| DeepSeek Anthropic Messages | `https://api.deepseek.com/anthropic/v1` | `/messages` |
| 阿里百炼 ASR | `https://dashscope.aliyuncs.com/api/v1` | `/services/aigc/multimodal-generation/generation` |
| 自定义 Chat Completions | 例如 `https://example.com/v1`，按服务文档填写 | `/chat/completions` |
| 自定义 Anthropic Messages | 例如 `https://example.com/anthropic/v1`，按服务文档填写 | `/messages` |

套餐、地域与账号权限可能不同；编码套餐端点不能直接假设等同于通用端点。模型 ID 手动填写自己账号实际开通的值。MiniMax 接口模板与协议参考 [中国站 Messages 文档](https://platform.minimax.cn/docs/api-reference/text-anthropic-api)、[中国站 Chat Completions 文档](https://platform.minimax.cn/docs/api-reference/text-openai-api)，智谱参考 [API 快速开始](https://docs.bigmodel.cn/cn/api/introduction) 与 [Claude API 兼容说明](https://docs.bigmodel.cn/cn/guide/develop/claude/introduction)。本次没有使用用户真实 Token 进行厂商联调。

自定义连接需要提供兼容所选协议与当前鉴权方式的服务：Chat 使用 Bearer Token；Messages 还发送 `x-api-key`、`anthropic-version` 并允许透传 `anthropic-beta`。远程地址使用 HTTPS，本机可用回环 HTTP。表单内临时关闭再打开协议会保留手填端点；保存连接不会调用上游。客户端请求路径决定协议，模型必须启用该协议且连接必须配置对应端点；不自动转换 Chat／Messages。

DeepSeek 选择内置模板后填写自己的 API Key，再添加模型；可通过 Chat 协议“获取模型列表”选择当前可用 ID，也可手动填写。参考 [DeepSeek 首次调用 API](https://api-docs.deepseek.com/zh-cn/)、[Anthropic 兼容接口](https://api-docs.deepseek.com/zh-cn/guides/anthropic_api) 和 [模型列表](https://api-docs.deepseek.com/api/list-models/)。官网给 Anthropic SDK 的基础地址不含 `/v1`；本项目只追加 `/messages`，所以模板预先包含 `/v1`，与 [DeepSeek 官方 Harness 实现](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/web/web-search-deepseek/src/provider.ts) 一致。不内置固定模型清单；若 Messages 端点不提供列表，可切换 Chat 获取或手填。厂商特有请求参数按原协议透传，MiniMax 的专用参数转换不会应用于 DeepSeek。

同一个模型别名可分别通过 Chat／Messages 入口调用，项目只需授权一次。模型新建时默认启用该连接已配置的协议，可取消不支持的协议；连接新增协议后，已有模型需要编辑并勾选才启用。升级前的单协议连接和模型会保留原协议，不会自动增加新协议。

模型的调用别名是程序使用的 `model` 值。显示名称可以自由改；修改调用别名后需修改程序配置。保留别名、更换关联的真实模型时，已授权项目后续会使用新模型。

默认参数支持 `temperature` 与 `max_tokens`，只补充客户端未提供的值。MiniMax 模型的编辑表单另有按协议生效的思考设置：

| 设置 | 网关补充的参数 | 生效范围 |
| --- | --- | --- |
| Chat · 思考拆分：开启／关闭 | `reasoning_split: true / false` | MiniMax Chat Completions；控制思考与正文是否分开返回，不改变思考是否开启 |
| Messages · 思考模式：开启／关闭 | `thinking` 对象，`type` 为 `adaptive`／`disabled` | MiniMax Messages；M3 支持开关，M2 系列始终开启思考 |
| 不补充参数 | 不增加对应字段 | 由客户端或厂商默认值决定 |

两项均默认“不补充参数”。例如在 M3 上开启这两项，Chat 请求缺少 `reasoning_split` 时补 `true`，Messages 请求缺少 `thinking` 时补 `{"type":"adaptive"}`。默认参数不覆盖调用方显式字段，包括 `false`、`disabled` 或其他值；不递归合并 `thinking` 对象。随后独立执行下述厂商兼容规则。Chat 不自动补 Messages 的思考设置，Messages 不自动补 Chat 的拆分设置。模型改用其他厂商时这两项不生效；原配置保留，换回 MiniMax 后恢复。保存后新请求立即采用配置，无需重启。

网关对外保持统一的自定义模型接入，这项思考参数兼容无需修改客户端。内部按连接厂商、上游模型 ID 与协议应用兼容规则：当前 MiniMax M3 的 Messages 请求将 `thinking: {"type":"enabled","budget_tokens":8192}` 转为 `thinking: {"type":"adaptive"}`，没有预算字段的 `enabled` 也会转换。固定思考预算会被移除，`max_tokens` 总输出上限不变。已是 `adaptive`、明确 `disabled` 或未传 `thinking` 时不做此转换；不影响 Chat、MiniMax M2 或智谱等其他厂商。同一项目可授权不同厂商的模型，它们共用项目凭证，但各用自己的内部规则。

请求详情会直接显示“网关参数适配”，列出转换前后的字段值及移除的思考预算。旧记录没有转换记录，不会补显示。请求记录的输入仍为客户端原始请求，不包含网关补充的默认参数；响应原样转发，流式结束和 TTFT／TTFC 的解析规则保持现状。拆分参数不保证 TTFT／TTFC 一定不同，实际取决于上游是否返回独立思考事件及其到达时间。客户端传入的其他厂商参数、工具定义、工具调用、结果及思考内容块按原协议保留；网关不执行工具，也不自动拼接会话上下文。具体参数是否支持仍由厂商决定。

厂商连接页负责配置端点与凭据，不提供测试入口。配置模型后，在模型页点击“测试”；“测试模型”弹窗先选择协议并显示将调用的具体连接与模型，点击“发起测试”才进行实际请求。项目试调用也可选择模型可用的协议。真实连接会使用厂商额度，保存配置本身不会触发调用。

### 模型列表接口

查看网关提供的全部模型，无需项目 Token 或管理登录，可直接用浏览器打开 [公开模型目录](http://127.0.0.1:8317/api/public/models)，或执行：

```bash
curl http://127.0.0.1:8317/api/public/models
```

返回示例（`coding` 为示例别名）：

```json
  "data": [

      "id": "coding",
      "object": "model",

      "protocols": ["chat", "messages"]
```

`id` 是调用时填写的 `model` 值；`chat` 对应 `/v1/chat/completions`，`messages` 对应 `/v1/messages`。目录按别名排序，只展示模型与连接均启用且至少有一种可用协议的模型；配置修改后下次查询立即反映。无可展示模型时返回 `data: []`。接口只查询本地配置，不请求厂商、不消耗模型额度，也不表示上游实时健康。

```bash
curl http://127.0.0.1:8317/v1/models \
  -H "Authorization: Bearer 你的项目Token"
```

公开目录不返回厂商端点、上游模型 ID、项目授权或凭据；看到模型不等于有权调用，实际调用仍需有效项目 Token 和该模型授权。公开接口携带 Token 时也返回同一份全网关目录。无需 Token 仅指接口认证规则，当前回环监听仍只供本机访问；它不会自动开启局域网或公网访问。

## 权限与密钥的实际行为

- 管理员使用 HttpOnly、SameSite 严格模式会话，项目使用独立的高熵随机凭证。管理接口逐次校验会话、Host／Origin，以及修改请求的专用标记。
- 项目鉴权使用 SHA-256 摘要；为支持管理员后续复制，项目 Token 另以 AES-256-GCM 加密保存，认证数据为 `project:` 加项目 ID，与厂商凭据分隔。新建和重置时密文与摘要在同一事务保存，写入失败全部回滚。允许模型关系保存在 SQLite 中，每次请求重新查询；停用、取消授权、重置凭证对后续请求生效。不会默认终止已经开始的流式请求。
- 厂商 Token 使用 AES-256-GCM 加密，关联连接 ID 作为认证数据。随机主密钥由管理密码通过 Argon2id 派生的密钥加密包裹；数据库没有明文主密钥或管理密码。
- 本次 Argon2id 参数为 64 MiB 内存、3 次迭代、2 路并行。登录及凭据再验证均有短时间尝试次数限制。
- 本机免密模式完成首次激活后，重启自动就绪；未登录、关闭管理页、会话过期或点击“退出管理”都不影响模型调用。标准密码模式重启后仍需人工解锁。兼容保留的 `POST /api/admin/lock` 才会显式清除内存主密钥和全部管理员会话；页面退出使用独立的 `POST /api/admin/logout`。
- 管理列表不返回 Token。厂商 Token 在标准模式下仍需再次验证管理密码才能查看，本地临时免密模式允许留空，20 秒后隐藏；项目 Token 可由已解锁管理员主动复制，正常情况下不在页面显示原文。调用接口不携带管理员 Cookie，不向客户端转发厂商鉴权头。
- 数据目录权限为 0700，数据库为 0600。记录中的输入输出仍为可读内容，不等同于整个数据库加密。操作系统账号、已登录浏览器和服务进程的权限仍是信任边界。

## 记录与性能边界

模型调用从入口建立监控记录，身份错误、授权拒绝和格式错误同样计数。未通过前置校验时不保存原始请求体。管理员模型测试也计入调用，管理接口的密码和 Token 提交不记入调用日志。

SSE 按完整事件及时转发，不等待整个响应完成；复用上游 HTTP 连接，客户端取消会传递给上游。记录通过有界队列写入，队列或磁盘写入失败会显示未写入计数，不承诺异常退出时零丢失。

请求体上限 2 MiB，普通响应读取上限 8 MiB，单条记录的输入和输出分别最多 1 MiB；超出记录上限会标注截断。当前列表显示最近 200 条，详细原始事件仍可逐条查看。没有自动清理历史，长期使用需关注磁盘容量。

请求列表支持项目、模型、厂商三个下拉条件，与完成状态及关键词搜索取交集，显示匹配数／已加载数，可点击“清除”一次恢复全部。筛选仅作用于当前加载的最近 200 条，不查询全库。模型按配置 ID 归并，保留改名前的调用及已删除模型；未匹配模型的请求按原调用别名单独筛选。厂商使用请求当时保存的厂商类型（如智谱、MiniMax、自定义），不按当前连接重新推断历史；缺少该字段的旧记录或前置拒绝请求归入“未记录厂商”。菜单支持鼠标及键盘操作、深浅配色与手机布局。

总览提供六组监控，支持近 1 小时、24 小时、7 天和“全部”，可结合项目、连接、模型和流式筛选，每 5 秒刷新。“全部”汇总从监控开始采集至今的数据，重启后继续累计；趋势图按完整范围划分 24 个时段，近期调用仍显示最近 8 条。统计从升级到监控版本时开始，旧日志仍可在请求记录中查看，不推算为完整历史统计。

“模型表现”默认按请求数从多到少排列，未路由请求始终在最后。点击数据表头切换升序／降序，输入与输出 Token 可分别点击；TTFT／TTFC 首次点击从低到高，其余指标从高到低。缺失值排在有效数值之后，零值正常参与排序；当前页面内刷新及筛选保留所选排序，点击模型仍可筛选。

TTFT（Time to First Token）从开始转发计时，到首段有效思考、正文或工具内容。TTFC（Time to First Content，项目定义）使用同一起点，只统计首段非空正文。新非流式请求不记录首字；成功但没有正文显示“无正文”，工具调用本身不算失败。总耗时包含网关鉴权和转发，旧记录仍沿用原来的转发阶段耗时。

输入总量、输出总量、缓存读取和写入取厂商报告；Chat 缓存命中包含在输入内，Messages 的输入总量需要相加普通输入、缓存读取和缓存写入。缺失显示“—”，明确零才显示 0。用量完整率针对已转发且已结束的请求；缓存命中占比仅按有缓存信息的请求计算。输出速度与 TPOT 根据有效输出阶段估算，缺少可靠用量、样本不足、失败或非流式时不计算。模拟模型明确报告零真实消耗，不用其速度代表厂商模型。

请求成功率按成功／（成功＋失败）计算，包含网关拒绝，排除进行中与客户端取消。流式 HTTP 200 后仍可能发生错误，最终结果会单独标注。时延 P50／P95 只采样成功请求，首响和速度仅采样流式；不要混淆不同模型、回答长度和流式模式。

监控摘要独立持久化，不依赖正文日志队列。统计写入失败时总览明确告警；磁盘故障仍可能影响完整性。重启时遗留的进行中请求标为异常中断。进行中请求和正文日志缺失的请求可查看监控摘要，无法恢复没有保存的正文。

## Linux 迁移准备

纯 Go SQLite 驱动不依赖 CGO。已经成功交叉构建 Linux amd64 与 arm64 二进制；尚未在真实 Linux 主机运行。前端构建一次后，可构建目标系统二进制：

```bash
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 bash scripts/go.sh build -o bin/gateway-linux-amd64 ./cmd/gateway

```

Linux 建议仍监听回环地址，通过 SSH 隧道访问，或使用 HTTPS 反向代理。后者配置 `--public-url https://你的域名`，管理页面只接受这个地址；非回环监听强制要求 HTTPS public-url。反向代理需关闭 SSE 缓冲。这里实现的是配置与构建准备，没有在真实 Linux 主机部署验证。
