# 管理页面配置与项目权限设计

更新日期：2026-09-16

## 1. 已确认的需求与当前建议

用户已确认：采用 A 的整体结构＋B 的请求详情页；连接与模型可在管理页面配置，包括直接填写厂商 Token、修改模型名称。技术栈、只做 LLM 的首版范围和 Linux 迁移准备保持不变。

用户已同意按本设计实现第一版 Demo。核心配置、加密保管、独立项目凭证和模型授权现已实现，实际行为与限制见 [Demo 使用说明](demo.md)。不预先建立多用户、组织或复杂角色系统。原三版静态界面稿仍只是设计来源，不能用于保管真实凭据。

整体关系：**你配置连接 → 模型绑定连接 → 项目获得模型权限 → 程序用项目凭证调用网关**。一个连接可以服务多个模型，一个模型可以授权给多个项目。

## 2. 连接页：决定请求发到哪里、使用哪个厂商 Token

连接列表显示名称、厂商、协议、端点、凭据配置状态及启停状态。提供新增、编辑、更换 Token、停用和删除操作；实际调用在模型页测试。删除窗口直接列出关联模型与授权项目；支持列表内逐个删除模型，以及一键级联删除连接、全部关联模型和对应授权。项目与历史请求保留，服务端在事务内核对关联模型列表并执行删除，列表变化时要求刷新后重新核对。

| 表单字段 | 行为 |
| --- | --- |
| 连接名称 | 用户自定义，例如“智谱主连接”“MiniMax 开发用途” |
| 厂商／接口协议 | 选择智谱、MiniMax 模板或自定义连接；Chat Completions／Anthropic Messages 可独立启用，至少一种，也可两种同时启用，共用此连接的 Token；不做协议互转 |
| API 端点 | 每个已启用的协议分别填写基础端点；模板预填，自定义手填。含版本路径，不含末尾调用路径；套餐对应地址在接入时核实 |
| 厂商 Token | 用户直接在密码输入框粘贴；已有凭据显示“已配置”，编辑其他字段不要求重复输入 |
| 状态 | 启用／停用；保存前展示受影响的模型与项目 |

正式软件的保存流程：已登录的管理员填写 Token → 管理接口接收 → Go 服务加密保存 → 页面只接收配置状态并清空输入框。主密钥与数据库分开管理，复用 README 中的跨平台解锁边界。Token 不写进项目配置、浏览器持久存储或管理请求日志。

保留用户最初要求的人工查看能力：列表与普通读取接口不返回原文；管理员主动点击“解锁查看”并通过额外验证后，专用接口才返回该条凭据，显示结束后清除。项目调用凭证没有访问此接口的权限。若 AI 能控制已解锁的管理浏览器，该界面本身不能继续保证对 AI 隐藏秘密。

连接保存时校验地址与必填项，不提供独立的端点检测。配置模型后，在模型页点击“测试”，由“测试模型”弹窗选择要测试的协议，明确显示所用连接、模型与实际调用提示。保存配置本身不自动触发模型调用。不得为了测试自动跟随重定向并把 Token 转发到未经批准的其他主机。

## 3. 模型页：决定程序填写的名称对应哪个实际模型

模型列表显示名称、调用别名、连接、厂商模型 ID 和状态。新增／编辑页面支持以下字段：

| 字段 | 例子与修改影响 |
| --- | --- |
| 显示名称 | “我的代码模型”，只影响管理界面 |
| 调用别名 | `coding`，程序请求中的 `model` 值；必须唯一，修改后程序也需更新 |
| 厂商连接 | 从连接页已有配置中选择 |
| 启用的调用协议 | 从连接已配置的协议中选择一种或两种；两种协议共用同一个模型别名与项目授权 |
| 厂商模型 ID | 填写账号实际开通的模型 ID；必须符合厂商要求，不能任意命名 |
| 默认参数 | 只展示对应适配器已支持的参数，如输出上限、采样参数、思考选项；不假设所有厂商语义相同 |
| 状态 | 启用／停用 |

支持手动填写模型 ID，不依赖厂商一定提供完整模型列表。自动拉取模型列表可以后续增加。

模型在数据库里有不可变的内部 ID；项目授权引用内部 ID。修改显示名称不会破坏权限。保留调用别名、更换实际模型后，程序无需改配置，但后续请求会使用新模型；保存前显示受影响项目，避免无意扩大可用模型的实际范围。

默认参数只用于补充客户端未传值，不当作强制权限约束。需要强制的上限应另设明确限制字段；首版不把精细费用预算和并发额度作为交付前提。

## 4. 项目页：独立调用凭证与模型授权

项目在这里代表一个调用方，例如代码助手、写作工具；它不是文件夹，也不是必须绑定某个开发平台的仓库。

你创建项目、勾选允许使用的模型，网关生成该项目的随机访问凭证。首版每个项目一个有效凭证即可，支持重置和停用。数据库保存不可逆校验摘要及可识别前缀，并另存 AES-256-GCM 加密副本，供已解锁管理员在“接入信息”中复制。普通项目凭证不能访问取回接口。旧版只有摘要的项目可以提交原有效 Token 验证并加密保存，升级不自动重置。这里的高熵随机凭证与用户自选密码使用不同的存储校验设计。

项目接入页面提供网关端点、该项目的凭证及可用模型别名，可分别复制端点或完整 Token，也可一次复制包含三项的接入配置。项目中的 API Key 字段填的是网关凭证，厂商 Token 仍留在连接配置中。网页项目应把调用凭证保存在自己的服务端，不放到公开网页代码里。

| 操作 | 你：管理员 | 项目 A 凭证 | 项目 B 凭证 |
| --- | --- | --- | --- |
| 调用模型 | 管理员另用显式测试功能 | 仅 A 获授权模型 | 仅 B 获授权模型 |
| 列举可用模型 | 全部配置 | 仅 A 获授权且已启用的模型 | 仅 B 获授权且已启用的模型 |
| 新增／修改连接、模型与 Token | 允许 | 不允许 | 不允许 |
| 解锁查看厂商 Token | 额外验证后允许 | 不允许 | 不允许 |
| 取回／复制项目 Token | 解锁后允许 | 不允许 | 不允许 |
| 修改项目授权、重置凭证 | 允许 | 不允许 | 不允许 |
| 检索历史请求与响应 | 可查看全部，并按项目筛选 | 首版不提供日志读取权限 | 首版不提供日志读取权限 |

普通调用仍会把本次响应返回给发起项目。表中限制的是额外检索历史内容的接口。未来若开放项目自查记录，所有列表、详情与导出均须以已认证项目 ID 限定范围，不能只靠前端筛选。

### 正常调用流程

1. Go 服务校验请求携带的网关凭证，确定其绑定项目及启用状态。
2. 根据调用别名解析内部模型 ID，检查项目授权及模型、连接启用状态；根据请求路径确定协议，检查模型已启用且连接已配置对应端点。
3. 通过检查后，由服务端取得相应厂商 Token 并向已配置端点转发。
4. 返回响应，调用记录由服务端标注项目 ID、模型 ID 和连接 ID。

新项目默认没有模型权限，必须明确勾选。程序提交的项目名称、文件夹路径、`project_id` 或 Token 前缀都不构成身份依据；权限来自服务端校验成功的凭证关联。程序也不能提交任意连接 ID、上游 URL 或厂商 Token 来绕过模型授权。

模型和项目均支持确认后删除：删除模型时原子移除项目授权，删除项目时移除凭证校验信息、加密副本和授权；其他连接、模型、项目与历史请求不随之删除。已删除模型的别名可以重新使用，但新模型必须重新授权。具体操作和验证见 [Demo 删除配置说明](demo.md#删除配置)。

普通响应、SSE、已支持的另一种协议入口及模型列表均须经过对应权限校验。改权限、停用项目或重置凭证后，后续新请求按最新状态执行；首版不承诺中断已经开始的流式请求。

### 最少的数据关系与接口边界

使用一套 SQLite 数据即可：连接、模型、项目、项目凭证、项目—模型授权、调用记录。共享厂商连接不等于项目互相拥有权限；无需按项目建立独立数据库或独立网关进程。

管理接口使用单独的管理员登录与会话认证；模型调用接口使用项目凭证。不是仅把接口放在两个路径下，也不能因为请求来自 `localhost` 就当作管理员。管理页面采用同源访问与请求来源／CSRF 校验，迁移 Linux 后使用 HTTPS。当前本机模式首次需用原管理密码激活，此后启动自动解锁，管理页可空白登录；退出管理仅撤销当前会话，不影响项目调用。保留原密码和数据，移除开关后恢复标准密码登录，详见 [本地临时空白解锁](demo.md#本地临时空白解锁)。

首版逐次从本地数据读取权限即可，不预先加分布式缓存、JWT 权限快照或外部鉴权服务。管理员修改配置后，下一次请求使用最新数据。实施时检查查询与索引开销，再决定是否需要缓存。

## 5. 隔离边界

这套方案提供网关内的调用授权与记录归属隔离，前提是各项目凭证彼此保密。**谁持有某项目凭证，就能以该项目权限调用。** 给两个程序填同一个凭证时，网关会把它们视为同一身份，无法仅凭请求证明来自哪个程序。

如果某个 AI Agent 能读取其他项目配置、网关解锁材料，或控制已经登录的管理浏览器，仅靠网关应用权限不能阻止它取得其他身份。需要更强隔离时，可在后续部署中限制 Agent 文件／浏览器权限，或将网关与凭据保管进程放到独立操作系统账号或受控 Linux 服务中。迁到 Linux 本身不会自动完成这些隔离。

本方案也不默认隔离厂商账号的余额、额度与限流；多个项目共用同一个厂商账号时仍可能共享这些资源。确有需求时再增加项目用量限制，或给不同项目配置独立厂商连接。

## 6. 实施时的关键验证

Demo 集成测试已覆盖：项目 A 无法调用只授权给 B 的模型；伪造 `project_id` 不改变身份；项目凭证无法访问管理与历史查询接口；模型列表不泄露未授权配置；撤销凭证后新请求被拒绝；原始请求／响应展示排除网关添加的鉴权数据；修改模型显示名称不影响已有调用与授权。测试使用假凭据和模拟上游，未使用用户真实 Token。

授权设计参考 [OWASP Authorization Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html) 的默认拒绝、服务端校验、每次请求校验与对象权限原则；凭据生命周期参考 [OWASP Secrets Management Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Secrets_Management_Cheat_Sheet.html)。这些来源支持安全原则，具体字段与首版范围属于本项目的设计选择。
