技术栈已确定：Go＋React／TypeScript＋Vite＋SQLite。本文保留三版原始界面稿的比较记录；三版稿中的数据均为示例。用户选定 A＋B 后，已实现独立的可运行 Demo，见 [Demo 使用说明](../demo.md)。

用户已确认采用 **A 的整体结构＋B 的请求详情页**。侧栏保留概览、请求记录、连接、模型、项目；请求记录采用 B 的列表与检查器。以下 A／B／C 描述保留为设计来源。

用户进一步要求：连接可在页面新增、修改并配置厂商 Token；模型名称与模型配置可以修改。可运行 Demo 已补齐对应编辑流程；历史示例稿没有接入真实存储。

## 共同范围

第一版只管理大语言模型。三版都围绕网关状态、智谱／MiniMax 连接、模型别名、项目访问权限、请求与响应查看展开。没有加入 ASR、视频、媒体任务、计费充值或自动选模型等后续功能。

## A：日常控制台

- 侧边导航，概览居中；以少量关键指标、厂商状态和近期请求建立全局认识。
- 视觉：中性底色、柔和蓝色强调、留白充分，表格与卡片保持清楚层次。
- 交互：切换概览／请求／连接／模型；筛选请求；点开详情；切换消息和原始数据。
- 优点：容易上手，适合日常检查状态和管理配置。
- 取舍：深度排查请求时，需要进入详情，信息密度低于 B。

## B：请求工作台

- 横向工具栏、请求列表与内容检查器并列；默认直接显示一条请求的消息结构。
- 视觉：细分隔线、紧凑布局、等宽元信息，像专注模型通信的调试工具。
- 交互：搜索／筛选并选择请求；切换消息、原始数据、耗时；暂停示例活动展示。
- 优点：最适合观察 Agent 的真实请求结构和工具调用，对学习网关最直接。
- 取舍：初次打开信息较多，连接与模型配置属于次要入口。

## C：项目空间

- 顶部导航、项目选择与项目详情；围绕一个工具查看接入方式、可用模型和请求。
- 视觉：更大间距、柔和暖色强调、以项目身份建立页面层次。
- 交互：切换项目；添加预览项目；查看接入配置；调整示例模型权限；查看项目请求详情。
- 优点：适合持续开发多个独立工具，明确哪个项目能使用什么模型。
- 取舍：跨项目排查请求需要切换到统一记录，全局比较不如 B 直接。

## 已确认的组合

采用 A 的侧栏与概览，结合 B 的请求列表、消息／原始数据／耗时检查器。项目仍是 A 侧栏中的管理页，借鉴 C 的模型授权与接入配置流程。

这一组合已由用户确认，并用于 React Demo。后续交互细节仍可调整。

2026-09-14：三版均通过浏览器交互检查，无脚本运行错误。验证了 A 的请求筛选与原始数据详情、B 的失败筛选／耗时／工具结果展开，以及 C 的项目切换／接入配置／模型权限／新增项目。
